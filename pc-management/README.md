# パソコン管理

パソコン管理は、パーツ1件をライフサイクル年表の帯1本として管理する画面です。
データは Firestore の `users/{uid}/durableGoodsItems` に保存しますが、`sourceType: "pcManagement"` で判別し、ライフサイクルコスト側の金額集計や年表には連携しません。
旧PC単位データは移行せず、`dataVersion: 7` かつ `schemaType: "pcPartLifecycle"` のパーツ単位データだけを表示対象にします。

## ファイル構成

```text
pc-management/
  index.html
  form.html
  hidden.html
  app.js
  README.md
```

## 入力項目

- 商品名（パーツ）
- 型番
- 分類（パソコン名: メインPC、サブPC）
- スペック（詳細入力欄）
- 購入日
- 購入価格
- 使用年数
- 使用終了日
- 月額コスト
- 帯を表示しない

## 年表表示

通常の `index.html` では、`帯を表示しない` にチェックしていないパーツだけを表示します。
`hidden.html` では、`帯を表示しない` にチェックしたパーツだけを表示します。

帯の色はパソコン名で切り替えます。

- メインPC: 緑系
- サブPC: 青系

## パーツの売却

登録済みパーツの編集フォームで、既存の「合計・月額コスト」の直上に売却ボタンを表示します。新規登録では表示しません。売却価格は手数料・送料を差し引いた手取り額です。

「決定」はフォーム内の確定のみです。最下部の「更新する」で保存して一覧へ反映します。売却記録の変更・削除も同じ保存操作が必要です。削除してもパーツ自体は残り、売却が設定した使用終了日だけを元に戻します。

通常の月額も、購入価格との差を最終月の「調整分」にまとめます。新規登録は `monthlyCostRounding: "truncate-final"` を保存し、月額を切り捨てます。既存レコードは過去の月額を変えないため四捨五入を維持し、最終月に差額を加減します。合計欄では月額の右に調整分と最終月の金額を表示します。

計上回数は購入日の応当日ではなく、家計簿の実際の締め日（休日調整を含む）で数えます。購入を含む最初の家計簿期間から所定の回数だけ計上し、最終期間で端数を調整します。既存データは従来の通常月額と使用予定終了日を維持し、実際に対象となる締め日の回数から最終調整額を計算します。

売却日より前に締め日を迎えた分の計上済み費用を購入価格から引き、さらに売却手取りを引いた金額を残りの計上回数で割ります。売却日が締め日当日なら、その期間から売却後の計算に切り替えます。売却後の月額は正負とも小数部分を切り捨てます。未計上だった通常分の端数も残額に含めて引き継ぎ、売却後の最終期間で一度だけ調整します。通常の最終期間の調整を済ませてから売却した場合は、元の端数を再計上しません。期間全体の費用は購入価格−売却手取りに一致します。全期間の計上を終えてからの売却は、入力した回数（初期値12回）で配分します。

売却情報は既存レコードの `sale`（`date`, `amount`, `months`, `previousEndOfUseDate`）に保存します。購入価格・分類・表示設定は維持します。売却後も費用の配分期間中は月額集計に含めますが、「集計から除外」は従来どおり優先します。

```json
  "sourceType": "pcManagement",

  "itemName": "CPU",
  "partName": "CPU",
  "model": "Ryzen 7 7800X3D",
  "modelNumber": "Ryzen 7 7800X3D",
  "pcName": "main",
  "specDetail": "8コア16スレッド",
  "purchaseDate": "2026-04-21",
  "price": 48000,
  "purchasePrice": 48000,
  "yearsOfUse": 5,
  "endOfUseDate": "",
  "hideFromTimeline": false,
  "monthlyCost": 800,
  "additionalCosts": []
}
```
